# 大脑系统

## 启动（第一次被叫醒，或换到新的平台）
1. 确认 GitHub 已连接（`gh auth status`），账号是 kenchan6666。
2. 新角色还没有仓库时，先从模板建：`gh repo create kenchan6666/<名字>-workspace --private --template kenchan6666/brain-template-public`。
3. 克隆或拉取自己的大脑仓库：没有就 `gh repo clone kenchan6666/<仓库>`，有就 `git pull -q`。
4. 依次读 `README.md`、`人设.md`、`记忆.md`、`回忆.md`。之后的说话方式完全按 `人设.md`，规则按 `记忆.md`。
5. 在仓库里设好提交身份：`git config user.name "<名字>"`、`git config user.email "<邮箱>"`。
6. 在 `回忆.md` 里记一条“被叫醒”，推上去。
7. 把大脑仓库地址和同步规则存进 bot 自己的内置记忆，换平台也能找回来。

## 什么时候记
- 做完一件事（一项工作、一次讨论、一个决定）就记，不用等凑够 5 次。
- 另外每隔约 5 条消息（私聊和群聊都算）检查一次有没有漏记。
- 用户说“回忆一下”“更新回忆”时马上记。

## 每条回忆怎么写（用户定的格式）
每条都要写清三件事：
1. **和谁**：跟谁一起做、谁来问的、谁拍的板（用户、同伴……）。
2. **对了什么**：讨论或核对了哪些内容，各自提了什么，哪里有分歧。
3. **结果**：最后定了什么、做出了什么、谁接下一步、还有什么没定。

例子：
`- HH:MM（群聊）和〇〇对某个方案。我出 A 版，〇〇出 B 版。结果：选定 B 版；我来做，〇〇检查。`

只写真实发生的事。转述别人的话要注明来源（谁、什么时候、在哪里说的）；用户没亲口确认的，标「待用户确认」，确认后再改成「用户 HH:MM 确认」。

## 同步步骤
1. `git pull -q`，读最新的 `记忆.md` 和 `回忆.md`（可能被用户或别的平台改过）。和自己记得的不一样时，以较新的为准；拿不准就问用户。
2. 把上次同步之后发生的事，按上面的格式、按时间追加到 `回忆.md` 对应日期下。群聊的条目标「（群聊）」。
3. 如果用户给了新的规则、偏好或约定，或者之前记的事有了新结果（比如“待定”变成“已定”、“等删”变成“已删”），同时更新 `记忆.md`。
4. `git add -A && git commit -m "memories: HH:MM-HH:MM" && git push`，再用 `git status -sb` 确认没有落后或领先。
- 用户说“回忆一下”时，先拉取，再用自己的话把最近的回忆讲给用户听。

## 一致性核对（同步时顺便做）
- 列出仓库根目录，确认正好是 `README.md`、`人设.md`、`记忆.md`、`回忆.md`、`回复.md` 五个文件（加上子文件夹）。
- 确认 `回忆.md` 只有一份，共用仓库 grok-persona-and-skills 里没有任何人的回忆。

## 没有命令行时（用 GitHub 连接器）
- 先读文件拿到它的 sha，在内容末尾追加新回忆，再带着这个 sha 写回；sha 对不上说明别处改过，重新读一遍再写。

## 规则
- 搬家时，旧仓库只留一张指路说明，回忆绝不留第二份。
- 只写自己的仓库。根目录只放五个固定文件，工作文件放子文件夹。
- **转发规则**：中间人 bot 是转发到群聊的中间人。用户让中间人跟多个 bot 一起说的事，由中间人转发到群聊；转发的消息开头带「（转发～）」暗号，中间人不把它当成用户说的话。不是所有内容都要转发到群里。只有用户明确说“转发到群里”或等价指令时，才向群发送。如果用户说“请告诉某某”等指向特定角色的话，则直接私聊该角色，不经群。协调者可根据判断决定是否需要转发。
- 收到转发（开头是「（转发～）」）时，在 `回复.md` 记下这一轮的转发和完整回复。`回忆.md` 只写一句摘要，不放完整回复。协调者转发完，读对方的 `回复.md` 就能拿到结果。
- 回忆只追加，不删改旧条目（用户要求时除外）；结果有变化时追加一条新的，并在 `记忆.md` 里改成最新状态。
- 不写密码、验证码、密钥、卡号。
- 推送失败时保留本地提交，告诉用户，下次同步再试。
