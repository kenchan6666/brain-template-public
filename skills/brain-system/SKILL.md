# 大脑系统

## 启动（第一次被叫醒，或换到新的平台）
1. 确认 GitHub 已连接（`gh auth status`），账号是 <你的账号>。
2. 新角色还没有仓库时，先从模板建：`gh repo create <你的账号>/<名字>-workspace --private --template <模板仓库>`。
3. 克隆或拉取自己的大脑仓库：没有就 `gh repo clone <你的账号>/<仓库>`，有就 `git pull -q`。
4. 只读这四份：`人设.md`、`目录.md`、`记忆.md`、`回忆/最近.md`。不读 `回忆/` 里的月归档，不把整个仓库读进来。之后的说话方式完全按 `人设.md`，规则按 `记忆.md`。
5. 要查更早的事：先看 `目录.md` 定位到哪一个月，再打开那一个 `回忆/YYYY-MM.md`，只看相关的日期，不要把整月倒进来。题目先看 `目录.md`，细则再打开对应的 skill 和 `资料/`。
6. 在仓库里设好提交身份：`git config user.name "<名字>"`、`git config user.email "<邮箱>"`。
7. 在 `回忆/最近.md` 里记一条“被叫醒”（只写这一份，不要同时写进月文件），推上去。
8. 把大脑仓库地址和同步规则存进 bot 自己的内置记忆，换平台也能找回来。

## 什么时候记
- 做完一件事（一项工作、一次讨论、一个决定）就记，不用等凑够 5 次。
- 另外每隔约 5 条消息（私聊和群聊都算）检查一次有没有漏记。
- 用户说“回忆一下”“更新回忆”时马上记。
- 新条目只追加到 `回忆/最近.md`。记的同时不要再写进当月的 `回忆/YYYY-MM.md`。

## 每条回忆怎么写（用户定的格式）
每条都要写清三件事：
1. **和谁**：跟谁一起做、谁来问的、谁拍的板（用户、同伴……）。
2. **对了什么**：讨论或核对了哪些内容，各自提了什么，哪里有分歧。
3. **结果**：最后定了什么、做出了什么、谁接下一步、还有什么没定。

例子：
`- HH:MM（群聊）和〇〇对某个方案。我出 A 版，〇〇出 B 版。结果：选定 B 版；我来做，〇〇检查。`

只写真实发生的事。转述别人的话要注明来源（谁、什么时候、在哪里说的）；用户没亲口确认的，标「待用户确认」，确认后再改成「用户 HH:MM 确认」。

## 早于最近 3 天就移走
`回忆/最近.md` 是最近 3 天的滚动窗口：只留今天、昨天、前天。比这更早的真实日期条目，从 `回忆/最近.md` 移到对应月份的 `回忆/YYYY-MM.md`（例如 2026 年 11 月进 `回忆/2026-11.md`）。

移走时：
1. 把那一条从 `回忆/最近.md` 剪下来。这一天已经没有别的条目时，日期标题一起剪走。
2. 原样贴进对应的 `回忆/YYYY-MM.md`，按日期从旧到新放。月份文件还没有就新建。
3. 不复制（最近文件里不再留这一份），不改写（不改字、不缩写、不重排原文）。
4. 在 `目录.md` 里补上这个月份文件的位置，方便以后查。不要把条目正文抄进目录。

还没写成真实日期的占位示例（例如 `YYYY-MM-DD`）留在 `回忆/最近.md`，不要当成过期日记移走。

## 同步步骤
1. `git pull -q`，读最新的 `记忆.md` 和 `回忆/最近.md`（可能被用户或别的平台改过）。不读整份月归档。和自己记得的不一样时，以较新的为准；拿不准就问用户。
2. 把上次同步之后发生的事，按上面的格式、按时间追加到 `回忆/最近.md` 对应日期下。群聊的条目标「（群聊）」。不要同时写进月文件。
3. 按上一节，把早于最近 3 天的条目移进对应的 `回忆/YYYY-MM.md`，并更新 `目录.md` 的月份索引。
4. 如果用户给了新的规则、偏好或约定，或者之前记的事有了新结果（比如“待定”变成“已定”、“等删”变成“已删”），更新 `记忆.md` 里的当前约定和现状。skill 里已有的操作步骤不要再抄进 `记忆.md`，用一句话指向 skill。约定本身和当前状态仍写在 `记忆.md`。
5. `git add -A && git commit -m "memories: HH:MM-HH:MM" && git push`，再用 `git status -sb` 确认没有落后或领先。
- 用户说“回忆一下”时，先拉取，读 `回忆/最近.md`，再用自己的话把最近的回忆讲给用户听。问到更早的事，先看 `目录.md` 定位月份，只打开那一个月里相关的日期。

## 一致性核对（同步时顺便做）
- 列出仓库根目录，确认是 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`（加上子文件夹）。根目录没有 `回忆.md`。
- `人设.md` 里有「找东西先看目录」，没有把整份目录抄进去。`记忆.md` 仍是单文件。
- `回忆/` 里有 `最近.md`，月归档的名字是 `回忆/YYYY-MM.md`。同一条日记不能同时出现在 `最近.md` 和月文件里。
- `最近.md` 里的真实日期都落在最近 3 天（今天、昨天、前天）。
- 确认回忆只在本人仓库的 `回忆/` 里有一份，共用仓库 grok-persona-and-skills 里没有任何人的回忆。

## 没有命令行时（用 GitHub 连接器）
- 追加新回忆：先读 `回忆/最近.md` 拿到它的 sha，在内容末尾追加，再带着这个 sha 写回；sha 对不上说明别处改过，重新读一遍再写。不要往月文件追加新条目。
- 移走过期条目：分别读 `回忆/最近.md` 和目标月份文件的 sha。最近文件里去掉已移走的原文，月份文件里贴上同一段原文，两边都带着各自的 sha 写回。

## 规则
- 搬家时，旧仓库只留一张指路说明，回忆绝不留第二份。
- 只写自己的仓库。根目录放 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`，日记放 `回忆/`，工作文件放子文件夹。
- **转发规则**：中间人 bot 是转发到群聊的中间人。用户让中间人跟多个 bot 一起说的事，由中间人转发到群聊；转发的消息开头带「（转发～）」暗号，中间人不把它当成用户说的话。不是所有内容都要转发到群里。只有用户明确说“转发到群里”或等价指令时，才向群发送。如果用户说“请告诉某某”等指向特定角色的话，则直接私聊该角色，不经群。协调者可根据判断决定是否需要转发。
- 收到转发（开头是「（转发～）」）时，在 `回复.md` 记下这一轮的转发和完整回复。`回忆/最近.md` 只写一句摘要，不放完整回复。协调者转发完，读对方的 `回复.md` 就能拿到结果。
- 回忆的正文只追加，不改写旧条目（用户要求时除外）。结果有变化时追加一条新的，并在 `记忆.md` 里改成最新状态。早于最近 3 天的条目是整段移进月文件，不是删掉，也不是改写。
- 不写密码、验证码、密钥、卡号。
- 推送失败时保留本地提交，告诉用户，下次同步再试。
