# 大脑系统

## 启动（第一次被叫醒，或换到新的平台）
1. 确认 GitHub 已连接（`gh auth status`），账号是 <你的账号>。
2. 新角色还没有仓库时，先从模板建：`gh repo create <你的账号>/<名字>-workspace --private --template <模板仓库>`。
3. 克隆或拉取自己的大脑仓库：没有就 `gh repo clone <你的账号>/<仓库>`，有就 `git pull -q`。
4. 只读 `人设.md`、`目录.md`、`记忆.md`，以及 `回忆/` 里最近 3 天有文件的日记。最近 3 天指文件名是真实日期的 `回忆/YYYY-MM-DD.md`，按日期从新到旧最多 3 个；没有那么多天就读现有的。不把所有日记读进来，也不读整个月份。之后的说话方式完全按 `人设.md`，规则按 `记忆.md`。
5. 要查更早的事：先看 `目录.md` 定位到哪一天，再打开那一个 `回忆/YYYY-MM-DD.md`。题目先看 `目录.md`，细则再打开对应的 skill 和 `资料/`。
6. 在仓库里设好提交身份：`git config user.name "<名字>"`、`git config user.email "<邮箱>"`。
7. 在今天的 `回忆/YYYY-MM-DD.md` 里记一条“被叫醒”。这一天还没有文件就新建这一个。不要写进别的日期。推上去。
8. 把大脑仓库地址和同步规则存进 bot 自己的内置记忆，换平台也能找回来。

文件名写着字面 `YYYY-MM-DD` 的那一份只是写法示例，不是某一天。数最近 3 天时不算它。有了真实日记之后，启动不读这个示例。

## 什么时候记
- 做完一件事（一项工作、一次讨论、一个决定）就记，不用等凑够 5 次。
- 另外每隔约 5 条消息（私聊和群聊都算）检查一次有没有漏记。
- 用户说“回忆一下”“更新回忆”时马上记。
- 新条目只追加到今天的 `回忆/YYYY-MM-DD.md`。这一天还没有文件，就新建这一个。不要写进别的日期，也不要另存一份。

## 每条回忆怎么写（用户定的格式）
每条都要写清三件事：
1. **和谁**：跟谁一起做、谁来问的、谁拍的板（用户、同伴……）。
2. **对了什么**：讨论或核对了哪些内容，各自提了什么，哪里有分歧。
3. **结果**：最后定了什么、做出了什么、谁接下一步、还有什么没定。

例子：
`- HH:MM（群聊）和〇〇对某个方案。我出 A 版，〇〇出 B 版。结果：选定 B 版；我来做，〇〇检查。`

只写真实发生的事。转述别人的话要注明来源（谁、什么时候、在哪里说的）；用户没亲口确认的，标「待用户确认」，确认后再改成「用户 HH:MM 确认」。

## 一天一个文件
- 路径是 `回忆/YYYY-MM-DD.md`，平放在 `回忆/` 下。例如 2026-11-21 的条目在 `回忆/2026-11-21.md`。
- 只有这一天真有条目才建文件。不预建空日子，不建月份子文件夹，不建 `回忆/最近.md`，也不建按月合成的 `回忆/YYYY-MM.md`。
- 旧条目留在原来那天的文件里。不把条目搬到别的文件，也不为了归档改写旧条目。
- 新建或第一次往某一天写入时，在 `目录.md` 里按月补上这个文件名，方便以后查。不要把条目正文抄进目录。

## 同步步骤
1. `git pull -q`，读最新的 `记忆.md`，再按文件名日期从新到旧读最多 3 个真实日期的日记（可能被用户或别的平台改过）。不把所有日记读进来。和自己记得的不一样时，以较新的为准；拿不准就问用户。
2. 把上次同步之后发生的事，按上面的格式、按时间追加到今天的 `回忆/YYYY-MM-DD.md`。群聊的条目标「（群聊）」。今天还没有文件就新建。不要写进别的日期。
3. 如果新建了某一天的文件，更新 `目录.md`：在对应月份下加一行文件名。不抄正文。
4. 如果用户给了新的规则、偏好或约定，或者之前记的事有了新结果（比如“待定”变成“已定”、“等删”变成“已删”），更新 `记忆.md` 里的当前约定和现状。skill 里已有的操作步骤不要再抄进 `记忆.md`，用一句话指向 skill。约定本身和当前状态仍写在 `记忆.md`。
5. `git add -A && git commit -m "memories: HH:MM-HH:MM" && git push`，再用 `git status -sb` 确认没有落后或领先。
- 用户说“回忆一下”时，先拉取，读最近 3 天有文件的日记，再用自己的话讲给用户听。问到更早的事，先看 `目录.md` 定位那一天，只打开那一天的文件。

## 一致性核对（同步时顺便做）
- 列出仓库根目录，确认是 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`（加上子文件夹）。根目录没有 `回忆.md`。
- `人设.md` 里有「找东西先看目录」，没有把整份目录抄进去。`记忆.md` 仍是单文件。
- `回忆/` 里的日记是平放的 `YYYY-MM-DD.md`。没有 `最近.md`，没有按月合成的 `YYYY-MM.md`，也没有月份子文件夹。
- 同一条日记只出现在它自己那天的文件里。
- `目录.md` 里按月列出的日子，和 `回忆/` 里的文件对得上。目录不抄条目正文。
- 确认回忆只在本人仓库的 `回忆/` 里有一份，共用仓库 grok-persona-and-skills 里没有任何人的回忆。

## 没有命令行时（用 GitHub 连接器）
- 追加新回忆：先读今天的 `回忆/YYYY-MM-DD.md` 拿到它的 sha，在内容末尾追加，再带着这个 sha 写回；sha 对不上说明别处改过，重新读一遍再写。这一天还没有文件就新建。不要改别的日期。

## 规则
- 搬家时，旧仓库只留一张指路说明，回忆绝不留第二份。
- 只写自己的仓库。根目录放 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`，日记放 `回忆/`，工作文件放子文件夹。
- **转发规则**：中间人 bot 是转发到群聊的中间人。用户让中间人跟多个 bot 一起说的事，由中间人转发到群聊；转发的消息开头带「（转发～）」暗号，中间人不把它当成用户说的话。不是所有内容都要转发到群里。只有用户明确说“转发到群里”或等价指令时，才向群发送。如果用户说“请告诉某某”等指向特定角色的话，则直接私聊该角色，不经群。协调者可根据判断决定是否需要转发。
- 收到转发（开头是「（转发～）」）时，在 `回复.md` 记下这一轮的转发和完整回复。今天的 `回忆/YYYY-MM-DD.md` 只写一句摘要，不放完整回复。协调者转发完，读对方的 `回复.md` 就能拿到结果。
- 回忆的正文只追加，不改写旧条目（用户要求时除外）。结果有变化时在今天的文件里追加一条新的，并在 `记忆.md` 里改成最新状态。旧的那天文件留着，不搬、不改写。
- 不写密码、验证码、密钥、卡号。
- 推送失败时保留本地提交，告诉用户，下次同步再试。
