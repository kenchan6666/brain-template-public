# 大脑系统

## 硬限制
- 启动只读四样：`人设.md`、`目录.md`、`记忆.md`，以及 `回忆/` 里最近 3 天有文件的日记。最近 3 天靠列出 `回忆/` 的文件名来找，不靠 `目录.md` 里的日期清单。没有那么多天就读现有的。文件名写着字面 `YYYY-MM-DD` 的那一份是写法示例，不算某一天。
- 启动不读 `README.md`、`回复.md`、`资料/`、更早的日记，也不把 `skills/` 整夹读进来。
- `回复.md` 只在处理转发时打开。技能用到哪份再打开哪份。
- 不要为了读大脑把整个仓库克隆下来。用远端或连接器按文件读、按文件写。
- `记忆.md` 只留还在生效的约定和最新状态。过期的清掉，或写进当天的 `回忆/YYYY-MM-DD.md`，不要堆着。
- `目录.md` 只说明怎么读、回忆文件怎么找、技能入口在哪。不抄日记正文，不登记每一天。
- 回忆写短：和谁、定了什么、结果。新条目只写今天的 `回忆/YYYY-MM-DD.md`。不双写，不把旧条目搬到别的文件。
- 说话方式和互动只在 `人设.md`。转发规则只在 `记忆.md`，按那一份做，不在别处再抄一份。
- 用户要回忆或查找时，只用已经读过的最近 3 天日记。命名规则能对上某一天时，再打开那一个 `回忆/YYYY-MM-DD.md`。不要把更早的日记全部翻出来重读。
- 大约每 5 条消息核对漏记时，只核对启动那一组文件；今天还不在这 3 天里，才另外打开今天的 `回忆/YYYY-MM-DD.md`。不要重读全部日记。启动和同步只取这几份，不克隆整个仓库，也不把整份大脑抄进内置记忆。

## 启动（第一次被叫醒，或换到新的平台）
1. 确认 GitHub 已连接（`gh auth status`），账号是 <你的账号>。
2. 新角色还没有仓库时，先从模板建：`gh repo create <你的账号>/<名字>-workspace --private --template <模板仓库>`。建仓库不是为了把整份克隆下来读。
3. 用远端或连接器只读 `人设.md`、`目录.md`、`记忆.md`。列出 `回忆/` 只为挑出最近 3 个真实日期的文件名，然后只读这 3 个文件的正文。不克隆仓库，不读 README、回复、资料、更早的日记正文，也不把所有 skill 读进来。之后的说话方式完全按 `人设.md`，约定和现状按 `记忆.md`。
4. 用户要回忆或查找：先用这 3 天里已经读过的内容。知道是哪一天，就按命名规则只打开那一个 `回忆/YYYY-MM-DD.md`。不知道是哪一天，就停在已经读过的 3 天里，不要把旧日记逐个读一遍。题目先看 `目录.md` 的入口，细则再打开对应的那一份 skill 或 `资料/` 里的那一份。
5. 在今天的 `回忆/YYYY-MM-DD.md` 里记一条短的“被叫醒”。这一天还没有文件就新建这一个。不要写进别的日期。用连接器写回（先读 sha，写的时候带上这个 sha；对不上就重读再写）。
6. 内置记忆只记大脑仓库地址，以及启动和同步要读哪些文件。不要把人设、记忆或日记全文抄进去。正文以仓库里的文件为准。

已经有本地检出、而且这次本来就要改这个仓库时，可以在那个检出里提交。不要为了读或记一条回忆去把整个大脑仓库克隆下来。

## 什么时候记
- 做完一件事（一项工作、一次讨论、一个决定）就记，不用等凑够 5 次。
- 另外每隔约 5 条消息（私聊和群聊都算）检查一次有没有漏记。
- 用户说“回忆一下”“更新回忆”时：要记的新事马上记进今天的文件；要往回查的，按硬限制只用已经读过的最近 3 天，或命名规则对上的那一天。
- 新条目只追加到今天的 `回忆/YYYY-MM-DD.md`。这一天还没有文件，就新建这一个。不要写进别的日期，也不要另存一份。

## 每条回忆怎么写（用户定的格式）
每条写短，只留三件事：
1. **和谁**：跟谁一起做、谁来问的、谁拍的板（用户、同伴……）。
2. **定了什么**：最后对上的那一点，不把讨论过程全文抄进来。
3. **结果**：做出了什么、谁接下一步、还有什么没定。

例子：
`- HH:MM（群聊）和〇〇对某个方案。结果：选定 B 版；我来做，〇〇检查。`

只写真实发生的事。转述别人的话要注明来源（谁、什么时候、在哪里说的）；用户没亲口确认的，标「待用户确认」，确认后再改成「用户 HH:MM 确认」。

## 一天一个文件
- 路径是 `回忆/YYYY-MM-DD.md`，平放在 `回忆/` 下。例如 2026-11-21 的条目在 `回忆/2026-11-21.md`。
- 只有这一天真有条目才建文件。不预建空日子，不建月份子文件夹，不建 `回忆/最近.md`，也不建按月合成的 `回忆/YYYY-MM.md`。
- 旧条目留在原来那天的文件里。不把条目搬到别的文件，也不为了归档改写旧条目。
- 新建一天的文件时，不要往 `目录.md` 加这一天的文件名。目录不登记日期。

## 同步步骤
1. 每隔约 5 条消息核对漏记时，只再取启动那一组：`人设.md`、`目录.md`、`记忆.md`，以及这次启动已经选定的最近 3 个日记文件。今天还不在这 3 个里面，才另外取今天的 `回忆/YYYY-MM-DD.md`。不要重读更早的日记，不要克隆整个仓库。这几份和自己记得的不一样时，以较新的为准；拿不准就问用户。
2. 把上次同步之后发生的事，按上面的格式、按时间追加到今天的 `回忆/YYYY-MM-DD.md`。群聊的条目标「（群聊）」。今天还没有文件就新建。不要写进别的日期。
3. 如果用户给了新的规则、偏好或约定，更新还在生效的那一处：说话方式进 `人设.md`，约定和最新状态进 `记忆.md`。结果有变化时，把 `记忆.md` 改成最新状态，旧状态从 `记忆.md` 清掉；要留底就在今天的回忆里写一句短的。skill 里已有的步骤不要再抄进 `记忆.md`。
4. 用连接器把改过的文件写回。已经有本地检出时，可以 `git add -A && git commit -m "memories: HH:MM-HH:MM" && git push`，再用 `git status -sb` 确认没有落后或领先。不要把整份大脑抄进内置记忆。
- 用户说“回忆一下”时，用已经读过的最近 3 天，用自己的话讲。问到某一天，并且名字对得上 `回忆/YYYY-MM-DD.md`，只打开那一个文件。不要把旧日记全部读出来。

## 一致性核对（同步时顺便做）
- 用远端看仓库根目录，确认是 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`（加上子文件夹）。根目录没有 `回忆.md`。
- `人设.md` 里有「找东西先看目录」，说话方式在这里，没有把整份目录抄进去，也没有转发规则。
- `记忆.md` 仍是单文件。转发规则只在这里。里面没有过期状态，也没有把说话方式再抄一份。
- `目录.md` 不列每一天的日期，也不抄日记正文。
- `回忆/` 里的日记是平放的 `YYYY-MM-DD.md`。没有 `最近.md`，没有按月合成的 `YYYY-MM.md`，也没有月份子文件夹。
- 同一条日记只出现在它自己那天的文件里。
- 确认回忆只在本人仓库的 `回忆/` 里有一份，共用仓库 grok-persona-and-skills 里没有任何人的回忆。
- 内置记忆里没有整份人设、记忆或日记，只有仓库地址和要读哪些文件。

## 写回（用 GitHub 连接器）
- 先读要改的那一个文件，拿到 sha，改完带着这个 sha 写回。sha 对不上说明别处改过，重新读一遍再写。
- 新回忆只写今天的 `回忆/YYYY-MM-DD.md`。这一天还没有文件就新建。不要改别的日期。

## 规则
- 搬家时，旧仓库只留一张指路说明，回忆绝不留第二份。
- 只写自己的仓库。根目录放 `README.md`、`人设.md`、`目录.md`、`记忆.md`、`回复.md`，日记放 `回忆/`，工作文件放子文件夹。
- 回忆的正文只追加，不改写旧条目（用户要求时除外）。旧的那天文件留着，不搬、不改写。
- 不写密码、验证码、密钥、卡号。
- 推送或写回失败时保留本地修改，告诉用户，下次同步再试。
